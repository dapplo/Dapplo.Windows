Class DataObjectReader

Namespace

Reads an OLE data object (IDataObject), from drag and drop or from GetOleDataObject(int, TimeSpan?). It supports what the Win32 clipboard API can't: formats with an index (lindex), IStream data and virtual files (FileGroupDescriptorW + FileContents, e.g. Outlook attachments). As IClipboardDataSource the same read helpers work as for the clipboard and snapshots.

Remarks

OLE data objects are COM objects: use the reader on the thread which got the data object (usually the STA UI thread), and only while the data object is valid (during the drop, or until the clipboard changes). Copy what you need, e.g. with TryGetStream(string, int, out Stream). TYMED_HGLOBAL and TYMED_ISTREAM are supported; TYMED_ISTORAGE (e.g. an Outlook message attached to a message), GDI and metafile handles are not.

The data comes from another application: treat it as untrusted. Failing or misbehaving sources make the Try methods return false, data larger than MaxDataSize isn't read, and virtual file names can contain paths: use SafeFileName to create files.

MaxDataSize

The maximum size of the data of one format (or one virtual file) in bytes, default 512 MiB. Larger data isn't read: TryGetStream(string, int, out Stream) returns false and OpenContent() null. This protects against data sources which claim or stream huge amounts of data.

TryGetStream(string, int, out Stream)

Get the data of a format with an index (lindex), e.g. FileContents of the virtual file with that index. The data is copied into a read-only MemoryStream, which stays valid after the data object is gone. Its buffer can be read without another copy with TryGetBuffer(out ArraySegment<byte>); don't change it.
