Remarks

Windows keeps two kinds of key state:

  • The asynchronous state (GetAsyncKeyState), used by IsDown(VirtualKeyCode) and IsAnyDown(params VirtualKeyCode[]): the state of the key right now, system wide, updated as soon as the input is processed, this includes input injected with SendInput. Use this from background threads, in a hook, or when waiting until the user released some keys. The async state is not updated for the key of the event which is currently being processed by a low-level hook, as the hook is called before the state changes. It reads as "up" while another desktop (e.g. the secure desktop with UAC or Win+L) is active.
  • The state of the message queue of the calling thread (GetKeyState), used by IsDownForCurrentThread(VirtualKeyCode) and IsToggled(VirtualKeyCode): the state at the time of the keyboard message which the thread is currently processing. Use this in a UI thread while handling a keyboard message, e.g. to check if Shift was down when the key which is being handled was pressed. It lags behind the real state when the thread doesn't process keyboard messages (a thread without windows or a busy UI thread). The toggle state (CapsLock, NumLock, ScrollLock) is only available in this state.

The generic keys Shift, Control, Menu and the pseudo key code Win are down when the left or the right key is down.

IsToggled(VirtualKeyCode)

Check if a toggle key is on (the low bit of GetKeyState), e.g. Capital (CapsLock), NumLock or Scroll. This is the state of the message queue of the calling thread, see the remarks of KeyboardState. For other keys the bit flips with every press, which is rarely useful.
