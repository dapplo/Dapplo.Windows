AvailableFormats(IEnumerable<string>, int)

The formats of preferred which are available on the clipboard right now, in the order of preferred, at most max. The clipboard isn't opened (IsClipboardFormatAvailable), so this never blocks or fails because another application has it open. Formats which Windows synthesizes (e.g. CF_DIB from CF_BITMAP, CF_UNICODETEXT from CF_TEXT) count as available.

public static IReadOnlyList<string> AvailableFormats(IEnumerable<string> preferred, int max = 2147483647)

Parameters

preferred IEnumerable<string>

the format names in the order of preference, null or empty names are ignored, duplicates are returned once

max int

int with the maximum number of formats to return, default all

Returns

IReadOnlyList<string>

list with the available format names, as passed in preferred

Remarks

Reading a format makes the application which copied render it, which can be slow (e.g. large images in several formats). Use this to pass only the formats you need to ReadSnapshotAsync(IEnumerable<string>, ClipboardAccessOptions, CancellationToken), e.g. the best two image formats: the second one is a fallback when the first can't be decoded. The clipboard can change between this call and the read: the snapshot then simply has fewer formats.

Exceptions

ArgumentNullException

When preferred is null

ArgumentOutOfRangeException

When max is negative

public static DataObjectReader GetOleDataObject(int retries = 5, TimeSpan? retryInterval = null)

Parameters

int with the number of retries when another application has the clipboard open (CLIPBRD_E_CANT_OPEN), default 5

Returns

Remarks

OLE requires an STA thread on which OLE is initialized (every WinForms / WPF UI thread is one), unlike the rest of this library. Use the reader on that thread, keep the usage short and dispose it: the data object is a snapshot of the clipboard at this moment.

Exceptions

When called on a thread which isn't STA, or on which OLE isn't initialized

When OleGetClipboard fails otherwise

UseAsync<T>(Func<IClipboardAccessToken, T>, ClipboardAccessOptions, CancellationToken)

Use the clipboard: wait asynchronously until it can be opened, then open it, run work and close it again, synchronously on one thread. This is the recommended way to access the clipboard from async code.

public static Task<T> UseAsync<T>(Func<IClipboardAccessToken, T> work, ClipboardAccessOptions options = null, CancellationToken cancellationToken = default)

Parameters

work Func<IClipboardAccessToken, T>

Func which reads or writes the clipboard via the token and returns a result

options ClipboardAccessOptions

optional ClipboardAccessOptions (owner, retries, retry interval, lock timeout)

cancellationToken CancellationToken

CancellationToken, cancels the waiting

Returns

Task<T>

Task with the result of the work

Type Parameters

T

Type of the result

Remarks

  • Works on any thread, no STA thread is needed.
  • Only the waiting is asynchronous. The awaits run on the context of the caller, so the work runs there too (e.g. the UI thread).
  • work must not be async: never await while the clipboard is open, the token is only valid until the work returns. Read the data into memory and process it after UseAsync returns; prepare the data to write before calling UseAsync.
  • Don't call Access(nint, int, TimeSpan?, TimeSpan?), AccessAsync(nint, int, TimeSpan?, TimeSpan?, CancellationToken) or UseAsync inside the work, the in-process lock isn't reentrant.

Exceptions

ClipboardAccessDeniedException

When the clipboard couldn't be opened, or the in-process lock timed out
