Class ClipboardSnapshot

Namespace
Dapplo.Windows.Clipboard

A copy of clipboard formats in memory, read in one short clipboard session with ReadSnapshotAsync(IEnumerable<string>, ClipboardAccessOptions, CancellationToken) or ReadSnapshot(IClipboardAccessToken, IEnumerable<string>, long). Decoding, saving or uploading the data happens afterwards, while other applications can use the clipboard again. The snapshot doesn't change when the clipboard changes, and can be used on any thread. Request only the formats you need, reading a format makes the application which copied render it: AvailableFormats(IEnumerable<string>, int) selects them without opening the clipboard.

TryUseVirtualFiles<T>(Func<IReadOnlyList<VirtualFile>, T>, out T, long)

Use the virtual files (FileGroupDescriptorW + FileContents, e.g. Outlook attachments) of the clipboard content this snapshot was taken of. Their content can't be read with the Win32 clipboard API, it needs the OLE data object of the clipboard, and so an STA thread with OLE initialized (e.g. the UI thread). This takes the OLE data object only when the snapshot has a file group descriptor, this is an STA thread and the clipboard didn't change since the snapshot (SequenceNumber), lets use read the files, and releases the data object again.

public bool TryUseVirtualFiles<T>(Func<IReadOnlyList<VirtualFile>, T> use, out T result, long maxDataSize = 536870912)

Remarks

  • Include FileGroupDescriptorWFormat and FileGroupDescriptorFormat in the formats of the snapshot, see HasVirtualFiles(IClipboardDataSource).
  • The data object is only valid inside use: read the content there with OpenContent() and return materialized results. Calling OpenContent after use returned throws an ObjectDisposedException.
  • use runs synchronously on the calling thread; the clipboard isn't open meanwhile, but opening the OLE data object retries shortly (up to about 100 ms) when another application has the clipboard open.
  • Exceptions of use are passed on; failing to get the data object returns false.
