Remarks

This is a thin view on the underlying WindowMessage: everything set here is written directly to that message, so all subscribers see the same state, and the answer reaches Windows.

Answers (CanEndSession, Veto(string)) are only honoured when they are made synchronously inside OnNext, on the thread of the shared message window. As soon as there is an ObserveOn, SubscribeOn, an await or any other thread hop, the reply has already been sent to Windows.

When WM_ENDSESSION arrives with IsSessionEnding set, the process can be terminated at any time after OnNext returned, so save state synchronously.

Properties

CanEndSession

Only for WM_QUERYENDSESSION: the answer to Windows, true (the default) allows the session to end, false blocks it. The answer is written to the underlying WindowMessage (TRUE=1 / FALSE=0), all subscribers share it and the last one which sets it wins. Only honoured when set synchronously inside OnNext on the window thread. For WM_ENDSESSION this is always true and cannot be changed.

Veto(string)

Only for WM_QUERYENDSESSION: block the session end (sets CanEndSession to false) and optionally tell the user why, using ShutdownBlockReasonCreate. The reason is removed automatically when the following WM_ENDSESSION arrives.
