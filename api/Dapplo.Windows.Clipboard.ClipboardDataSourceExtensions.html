Remarks

Windows synthesizes CF_UNICODETEXT from CF_TEXT and CF_OEMTEXT on the clipboard, but other sources (e.g. a DataObjectReader for a drop) may only have CF_TEXT. For CF_UNICODETEXT such sources fall back like Windows: CF_TEXT decoded with the ANSI code page of CF_LOCALE when present, else the system ANSI code page; then CF_OEMTEXT with the OEM code page. The text ends at the first NUL. The open clipboard, a ClipboardSnapshot and the OLE clipboard (GetOleDataObject(int, TimeSpan?)) don't use the fallback: the clipboard synthesizes CF_UNICODETEXT itself, and a snapshot has exactly the formats which were requested.
